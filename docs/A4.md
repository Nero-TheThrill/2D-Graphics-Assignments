# A4 — 텍스처 입히기

A3에서 만든 장면에 텍스처를 입힌 사각형을 추가한다. 같은 이미지에서 서로 다른 부분을 골라 표시하고, 필터와 반복 설정에 따라 화면이 어떻게 달라지는지 확인한다. 애니메이션은 구현하지 않는다.

## 시작하기

`student/a4/texture.hpp`, `main.cpp`, `scene.vert`, `scene.frag`를 수정한다. A1의 Mesh, A2의 Object, A3의 Camera는 그대로 사용한다.

이미지 읽기와 카메라 호출은 제공된다. 텍스처를 GPU에 올리고, UV를 연결하고, shader에서 색상을 읽는 부분을 작성하면 된다. 집을 그리기 전 색상 모드로 되돌리는 코드도 main에 들어 있다.

- `assets/atlas.png`: 256×128 이미지. 64×64 색상 타일 8개가 4열×2행으로 들어 있다. 화살표로 위아래 방향을, 아래 숫자 0~7로 선택한 타일을 확인할 수 있다.
- `assets/checker.png`: 16×16 체크무늬. 필터와 반복 설정을 비교할 때 사용한다.

## 텍스처 설정

저장 형식은 `GL_RGB8`, 업로드할 데이터는 `GL_RGB`, `GL_UNSIGNED_BYTE`를 사용한다. 픽셀 행 정렬은 `glPixelStorei(GL_UNPACK_ALIGNMENT, 1)`로 설정한다.

mip 레벨은 1개만 만든다. min/mag filter 모두 `GL_NEAREST` 또는 `GL_LINEAR`를 사용하고, mipmap을 요구하는 필터는 사용하지 않는다.

텍스처 객체 ID와 texture unit 번호는 서로 다르다. `glBindTextureUnit(0, texture.id)`는 객체를 0번 unit에 연결하는 호출이다. shader의 sampler에는 객체 ID가 아닌 **0**을 전달한다.

`NEAREST`는 주변 texel 중 하나의 색을 선택한다. `LINEAR`는 주변 texel의 색을 보간한다. 카메라를 확대해 체크무늬 경계가 어떻게 보이는지 비교한다.

## UV와 아틀라스

제공된 이미지 로더는 파일의 맨 위 행을 v=0에 업로드한다. 이미지가 똑바로 보이도록 quad 아래쪽 정점에는 v=1, 위쪽 정점에는 v=0을 지정한다.

타일 번호는 위쪽 행의 왼쪽부터 0~3, 아래쪽 행은 4~7이다. Sprite 두 개에 서로 다른 번호를 지정한다. 실행 중 번호를 바꾸는 기능은 필요하지 않다.

`atlasRect`에서 번호를 행과 열로 바꾼 뒤, 해당 타일의 UV 시작점과 크기를 계산한다. 나눗셈에는 실수를 사용한다. 예를 들어 4열×2행 아틀라스의 타일 5는 열 1, 행 1에 있으므로 보정 전 offset은 (0.25, 0.5), scale은 (0.25, 0.5)다.

계산한 영역은 제공된 `insetTile`에 전달한다. 이 함수는 LINEAR 필터에서 옆 그림의 색이 섞이지 않도록 경계를 반 texel 안쪽으로 줄여 준다. 함수 내부는 수정하지 않아도 된다.

vertex shader에서는 `uUvOffset + aUv * uUvScale`로 UV를 계산한다. 다른 타일을 표시하기 위해 VBO를 다시 만들 필요는 없다.

체크무늬에는 offset=(0,0), scale=(3,3)을 사용한다. 이 값은 main에서 제공된다. `insetTile`은 아틀라스에만 적용한다.

## 완료 기준

- 기존 집과 서로 다른 타일을 표시하는 Sprite 2개, 체크무늬 사각형이 보인다. 서로 가리지 않도록 배치한다.
- 카메라 이동·회전·줌이 장면 전체에 적용된다.
- F를 한 번 누르면 두 텍스처의 NEAREST/LINEAR 설정이 한 번 전환된다.
- V를 누르면 체크무늬의 REPEAT/CLAMP_TO_EDGE가 전환된다. 아틀라스는 CLAMP_TO_EDGE를 유지한다.
- REPEAT에서는 체크무늬가 반복되고, CLAMP_TO_EDGE에서는 범위 밖에 가장자리 색이 이어진다.
- 텍스처를 그린 다음 화면에서도 집의 색상이 정상적으로 보인다.

4. UV 범위를 0~3으로 지정했을 때 REPEAT와 CLAMP_TO_EDGE의 결과가 다른 이유는 무엇인가?
