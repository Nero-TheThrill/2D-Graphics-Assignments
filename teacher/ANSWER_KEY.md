# 교사용 정답 및 채점 안내

현재 학생용 A1~A4에 대응하는 참고 구현이다. A4는 애니메이션 없이 정적인 Sprite 두 개를 표시한다. 정점 좌표, 색, 이동 속도, 변수 이름이 같아야 하는 것은 아니다. 명세의 동작과 원리가 맞는지를 기준으로 평가한다.

## 실행

프로젝트 루트에서 다음 명령으로 각 정답을 실행한다.

```bat
build.bat solutions 1 run
build.bat solutions 2 run
build.bat solutions 3 run
build.bat solutions 4 run
```

`solutions/a1`부터 `solutions/a4`까지가 완성 코드다. 뒤 단계는 앞 단계의 정답 헤더를 직접 사용한다. 학생용 파일은 변경하지 않고 별도의 `build-solutions` 폴더에 빌드한다. 공통 제공 코드와 이미지는 프로젝트 루트의 `support`, `assets`를 사용한다.

학생 배포본에는 `solutions`와 `teacher`를 제외한다. 교사용 폴더만 따로 복사하면 공통 코드와 이미지가 빠지므로 전체 프로젝트와 함께 보관한다.

## A1 — 정점과 인덱스

### 구현 해설

참고 구현의 집은 정점 15개, 삼각형 7개, 인덱스 21개다. 벽을 먼저 그리고 지붕, 문, 창문을 그린다. 깊이 검사를 사용하지 않는 현재 설정에서 뒤에 그린 문과 창문이 벽 위에 보인다. 각 부분의 색을 유지하기 위해 정점을 분리했다.

VBO에는 `vertices.size() * sizeof(Vertex)`, EBO에는 `indices.size() * sizeof(unsigned)` 바이트를 올린다. 두 버퍼의 storage flags는 0이다. VAO의 binding 0에 VBO를 연결하고, 위치와 색상 attribute가 이 binding을 읽도록 설정한다. UV를 사용하지 않는 단계에서도 stride는 전체 `sizeof(Vertex)`다.

### 설명 문제 모범 답안

1. VBO는 정점 속성 데이터를, EBO는 정점을 참조하는 인덱스 데이터를 저장한다. VAO는 정점 속성의 형식과 버퍼 연결, 사용할 인덱스 버퍼를 기록한다.
2. attribute location은 shader 입력의 번호이고, buffer binding index는 VAO에서 정점 버퍼를 연결하는 슬롯 번호다. 위치와 색상은 각각 location 0과 1이지만 같은 VBO의 binding 0을 읽는다.
3. `glDrawElements`의 count는 읽을 인덱스의 개수다. 하나의 정점을 여러 삼각형이 참조할 수 있어 정점 개수와 다르다. 참고 구현에서는 정점 15개를 인덱스 21개로 참조한다.

### 채점 확인

- 집 정점·인덱스 25점: 네 부분이 구분되고 인덱스가 유효한가?
- DSA 버퍼·VAO 연결 30점: 바이트 크기, immutable storage, VBO/EBO 연결이 맞는가?
- attribute 설정 20점: component 수, offset, stride, binding, enable이 맞는가?
- draw call과 결과 15점: GL_TRIANGLES, 인덱스 count, GL_UNSIGNED_INT를 올바르게 사용하는가?
- 설명 10점: 세 객체와 두 종류의 번호를 구분하는가?

화면이 비면 drawMesh 호출, VAO bind, attribute enable 순으로 확인한다. 색이나 위치가 깨지면 stride와 offset을 확인한다. 그림의 미적 완성도는 점수 기준에 넣지 않는다.

## A2 — 모델 변환

### 구현 해설

열벡터 기준의 행렬은 다음과 같다. 코드에서는 열 순서로 배열에 저장한다.

```text
T = |1 0 tx|   R = |cosθ -sinθ 0|   S = |sx  0 0|
    |0 1 ty|       |sinθ  cosθ 0|       | 0 sy 0|
    |0 0  1|       |  0     0 1|       | 0  0 1|
```

기본 모델 행렬은 T*R*S다. 비교 모드는 S*R*T를 사용한다. 세 Object는 같은 Mesh를 가리키고 상태만 따로 가진다. 입력은 선택된 Object에만 적용한다. Q는 반시계, E는 시계 방향이며 Z는 축소, X는 확대다. R은 위치 (0,0), 각도 0, 크기 (1,1)로 되돌린다.

### 설명 문제 모범 답안

1. `T*R*S*p`에서 정점 p에 S가 먼저 적용되고, 그 결과에 R, 마지막으로 T가 적용된다.
2. 같은 로컬 정점 데이터라도 draw call마다 서로 다른 모델 행렬을 전달하면 다른 위치·크기·각도로 그려진다. VBO를 복사하거나 다시 업로드할 필요가 없다.
3. 한 화면 갱신마다 일정 거리만 이동하면 fps가 높을수록 빨라진다. 초당 속도에 dt를 곱하면 실제 경과 시간에 비례한 거리를 이동한다.

### 채점 확인

- 행렬과 곱 순서 25점, Mesh 공유 15점, 입력·시간 갱신 20점, uniform·shader 25점, 비교·설명 15점.
- 집을 오른쪽으로 옮기고 회전 및 크기를 바꿔 TRS/SRT를 비교한다. 원점에 그대로 두고 비교하면 차이를 보기 어렵다.
- 한 집을 선택해 움직였을 때 나머지 두 집이 변하지 않아야 한다.
- 정점 (1,0)에 scale=(2,3), 회전=90도, 이동=(4,5)를 적용하면 TRS 결과는 (4,7), SRT 결과는 (-10,15)이다.
- 제공된 선택·전환 코드를 그대로 사용해도 된다. 제공 코드 분량을 학생의 독자 구현으로 요구하지 않는다.

## A3 — 카메라

### 구현 해설

카메라의 월드 변환이 T(c)*R(θ)이므로 View는 R(-θ)*T(-c)다. 두 행렬의 순서를 뒤집고 각각 역변환을 취한다. 카메라 가시 높이를 H, framebuffer aspect를 a라 하면 폭은 H*a이고 CameraToNdc는 S(2/(H*a), 2/H)다.

참고 장면은 격자로 집을 배치하되 A4 텍스처가 놓일 중앙을 비웠다. 집 개수는 정답 조건이 아니다. 처음에 보이는 집과 이동 후 보이는 집이 모두 있으면 된다.

선택 실습 `cursorToWorld`도 구현되어 있으나 main의 `enableClickPlacement`는 false다. true로 바꾸면 클릭 배치를 확인할 수 있다. 커서의 논리 좌표를 NDC로 바꿀 때 Y를 뒤집고, camera 범위로 확대한 뒤 R(θ), T(c) 순서로 적용한다.

### 설명 문제 모범 답안

1. 카메라가 오른쪽으로 움직이면 고정된 물체는 화면에서 왼쪽으로 보인다. Object를 오른쪽으로 움직이면 해당 물체가 오른쪽으로 보인다. 두 경우 모두 카메라 회전이 없는 상태를 기준으로 비교한다.
2. Model: local → world. View: world → camera. CameraToNdc: camera → 정규화 좌표 범위. glViewport: NDC가 매핑될 framebuffer의 픽셀 영역을 설정한다. 엄밀히 vertex shader는 clip 좌표를 출력하지만 이 과제는 w=1이므로 perspective divide 후 xy가 그대로 NDC가 된다.
3. aspect=1600/800=2이므로 가시 가로 길이는 6×2=12다.

### 채점 확인

- View 25점, CameraToNdc·aspect 20점, 입력·줌 15점, 월드 구성 10점, shader·uniform·viewport 20점, 설명·결과 10점.
- 이동과 회전을 함께 적용해도 카메라 중심의 월드 점은 view 좌표 (0,0)이 되어야 한다.
- 창을 가로로 늘리면 더 넓은 월드가 보이고 집 자체가 가로로 늘어나면 안 된다.
- =는 확대, -는 축소이며 height는 2~20을 유지한다. C로 초기 상태로 돌아온다.
- 창을 최소화했다 복원해도 0으로 나누지 않아야 한다.
- 클릭 배치는 필수 100점에 포함하지 않는다.

## A4 — 텍스처

### 구현 해설

RGB8 텍스처 저장 공간을 한 레벨 할당한 뒤 RGB 바이트 데이터를 업로드한다. min/mag filter는 모두 NEAREST 또는 LINEAR다. quad의 색상은 흰색이고 UV는 이미지 로더에 맞춰 위쪽 v=0, 아래쪽 v=1로 둔다.

타일 번호 n에 대해 column=n%4, row=n/4다. 보정 전 offset=(column/4, row/2), scale=(1/4, 1/2)이며 실수 나눗셈을 사용한다. 제공 함수 insetTile로 경계를 보정한다. 예를 들어 타일 5의 보정 후 offset은 (0.251953125, 0.50390625), scale은 (0.24609375, 0.4921875)다.

아틀라스는 색상과 화살표로 구분되는 타일 8개다. 화살표 아래 숫자 0~7은 각 타일의 번호다. 참고 구현은 타일 0과 5를 정적으로 표시한다. F는 두 텍스처의 필터를, V는 체크무늬의 wrap만 전환한다. 체크무늬는 UV 0~3을 사용한다. 애니메이션이나 실행 중 타일 선택은 요구하지 않는다.

### 설명 문제 모범 답안

1. rasterizer가 삼각형 정점에 주어진 UV를 보간하여 fragment마다 UV를 만든다. 이 과제에서는 모든 정점의 w가 1이므로 화면상 삼각형에서 선형 보간으로 이해할 수 있다.
2. sampler는 어떤 texture unit을 읽을지 지정한다. 텍스처 객체를 unit에 연결하는 작업은 glBindTextureUnit이 담당한다. 따라서 unit 0을 사용하면 sampler에도 0을 전달한다.
3. NEAREST는 하나의 texel 색을 선택하므로 확대하면 픽셀 경계가 또렷하다. LINEAR는 주변 texel 색을 보간하므로 경계가 부드럽게 보인다.
4. REPEAT는 범위를 벗어난 UV를 반복시켜 패턴을 이어 간다. CLAMP_TO_EDGE는 가장자리 texel로 제한하므로 범위 밖에 가장자리 색이 늘어나 보인다.

### 채점 확인

- 생성·업로드 20점, quad·UV 연결 15점, sampler·shader 20점, atlas·두 Sprite 15점, 필터·wrap 비교 20점, 장면 유지·설명 10점.
- 같은 확대 배율에서 F 전환 결과를 비교한다. 축소된 전체 장면만으로 필터 차이를 판단하지 않는다.
- V를 바꿔도 아틀라스는 CLAMP_TO_EDGE를 유지해야 한다.
- 두 번째 화면 갱신 이후에도 집은 본래 색을 유지해야 한다. 색상 모드 복원은 제공 코드이므로 학생이 이를 새로 구현할 필요는 없다.
- 이미지가 뒤집히면 UV 방향을, 검게 나오면 업로드·min filter·texture unit·sampler 연결을 확인한다.

## 부분 점수와 후속 과제 지도

화면이 나오지 않는 경우에도 데이터·행렬·shader 연결을 항목별로 확인한다. 한 번의 연결 실수 때문에 모든 항목을 일괄 0점 처리하지 않는다. 앞 과제 때문에 다음 과제를 진행하지 못하는 학생에게는 이전 단계의 기준 구현을 제공하는 방식을 고려할 수 있다. 이 경우 학생이 작성한 부분과 제공받은 부분을 구분해 제출하게 한다.
