OpenGL Mathematics Library- GLM 
• Header Only
• It is a C++ mathematics library specifically designed for graphics software based on the
OpenGL Shading Language (GLSL) specifications.
• GLM provides classes and functions to handle common mathematical tasks in graphics
programming, such as vector and matrix operations, transformations, and more.
• Key Features of GLM
• Vector and Matrix Types: Types for 2D, 3D, and 4D vectors and matrices
• (e.g., vec2, vec3, vec4, mat2, mat3, mat4, quaternion).
• Transformation Functions:
• Functions for translation, rotation, scaling, and perspective transformations that are directly aligned with
OpenGL's way of handling transformations.
• Compatibility with GLSL:
• GLM is designed to mimic GLSL in terms of functionality and syntax, making it easier for developers to use in
conjunction with OpenGL shaders.
• Header-only Library:
• Being a header-only library means that it does not require separate compilation or linking, simplifying its
integration into projects.

Introduction to Matrices
• What is a Matrix?
• A matrix is a rectangular array of numbers arranged in rows and
columns.
• In computer graphics, matrices are used for various
transformations such as translation, rotation, and scaling.
• Importance in Computer Graphics
• Matrices allow us to perform complex transformations on objects
in a simple and efficient manner.
• They help in converting coordinates from one space to another
(e.g., from local space to world space, then to camera space, and
finally to screen space).

Uniform Variables in GLSL
• Uniform variables are global variables in shader programs that remain
constant for all vertices (in the vertex shader) or all fragments (in the
fragment shader) processed during a single rendering call.
• Used to pass data from the CPU application to the GPU shaders.
• Characteristics
• Global Scope:
• Uniforms are read-only variables that can be accessed by any shader stage (vertex,
fragment, etc.).
• Constant per Draw Call:
• Their value is constant for the duration of a draw call but can be changed between
draw calls.
• Usage:
• Commonly used for transformation matrices, lighting parameters, textures, and any
other data that is uniform (constant) across all vertices or fragments.

Prefix and Postfix Notation in Matrix 
Multiplication
• The terms "prefix" and "postfix" generally refer to the order in
which transformations (like translation, rotation, scaling) are
applied to objects.
• This is particularly relevant in matrix multiplication, where the
order of multiplication affects the result due to the non-
commutative nature of matrix operations.

Prefix Notation
• Prefix Notation (also known as Pre-Multiplication):
• Transformations are applied from right to left. This means
that the transformation matrix closest to the object being
transformed is applied first.
• For example, if you have matrices 𝑀1, M2, and M3, and you
multiply them as 𝑀=𝑀3×𝑀2×𝑀1, the transformation
represented by 𝑀1 is applied first, followed by 𝑀2, and finally
𝑀3.

Practical Example
• Consider the case where we want to apply a series of transformations to a vertex
in a 3D space. Let’s assume we have a vertex 𝑣 and we want to apply a scaling,
followed by a rotation, and finally a translation.
• Prefix Notation Example:
• In prefix notation, the transformations are specified in the order they are applied,
so if we want to:
• Scale by matrix S
• Rotate by matrix R
• Translate by matrix T
• The final transformation matrix would be:
• 𝑀=𝑇×𝑅×𝑆
• To transform a vertex 𝑣v, you would compute:
• 𝑣′=𝑀×𝑣=𝑇×𝑅×𝑆×𝑣
• This means that the vertex 𝑣 is first scaled, then rotated, and finally translated.

Matrix Conventions
• Column-Major vs. Row-Major
• Column-Major Order:
• OpenGL uses column-major order, meaning the matrix elements
are stored column by column.
• Row-Major Order:
• Some other graphics APIs like DirectX use row-major order, where
the matrix elements are stored row by row.
•5/23/2024 •22

--- PAGE 23 ---
Row-Major vs. Column-Major Layouts
• Row-Major Order:
• In row-major order, the matrix is stored in memory row by row.
• For a 4x4 matrix, the elements are stored in the following order:
• m[0], m[1], m[2], m[3],
• m[4], m[5], m[6], m[7],
• m[8], m[9], m[10], m[11],
• m[12], m[13], m[14], m[15]
• Column-Major Order:
• In column-major order, the matrix is stored in memory column by column.
• For a 4x4 matrix, the elements are stored in the following order:
• m[0], m[4], m[8], m[12],
• m[1], m[5], m[9], m[13],
• m[2], m[6], m[10], m[14],
• m[3], m[7], m[11], m[15]
•5/23/2024 •23

--- PAGE 24 ---
Column-Major Layouts
• OpenGL uses column-major order for matrices by
default.
• This means that when you pass a matrix to a shader, it
expects the matrix to be in column-major order.
• OpenGL and GLSL expect matrices in column-major
order by default.
• GLM also uses column-major order by default to align
with OpenGL.
• When initializing matrices in GLM, you can directly pass
them to OpenGL shaders without any reordering.

Scalar 
in GLSL
• In GLSL (OpenGL Shading Language), scalar types are the basic building blocks for
more complex data types like vectors and matrices. Scalars represent single values and
come in various types:
• Floating-Point Types
• float: Represents a single-precision floating-point number.
• double: Represents a double-precision floating-point number (available in GLSL 4.00 and
higher).
• Integer Types
• int: Represents a signed 32-bit integer.
• uint: Represents an unsigned 32-bit integer.
• short: Represents a signed 16-bit integer (available in GLSL 4.10 and higher).
• ushort: Represents an unsigned 16-bit integer (available in GLSL 4.10 and higher).
• int64_t: Represents a signed 64-bit integer (available in GLSL 4.60 and higher).
• uint64_t: Represents an unsigned 64-bit integer (available in GLSL 4.60 and higher).
• Boolean Type
• bool: Represents a boolean value (true or false).
